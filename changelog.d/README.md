Each change adds one file under `unreleased/<section>/`, named for its pull request (`75-short-slug.md`), holding one `- **Lead.** Detail.` entry; sections are `added`, `security`, `changed`, `removed`, `fixed` and `internal`. CHANGELOG.md is generated from these files by `scripts/changelog.py` (`task changelog`), so it is never edited by hand. A pull request adds its fragment and leaves CHANGELOG.md alone, so two open pull requests never conflict on it. The site deploys from every push to main and has no versioned releases; a numbered section names a rewrite, and is cut in its own pull request with `task changelog -- --release X.Y.Z`, which turns `unreleased/` into that section and regenerates the file. Entries from before fragments were adopted keep their text as `_intro.md`, in `unreleased/` and in each numbered section.
